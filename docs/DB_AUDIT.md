# KALIN live Supabase audit

**2026-11-23 (Asia/Manila).** Review of live PostgreSQL 17.11 catalog metadata, deployed Edge Function source and deployment settings, migration history, and the security and performance advisors. Frontend and design comparison used [README.md](../README.md) and the checked-in JavaScript. Verified means the live definition or advisor output establishes the stated behavior or configuration. Assumed means the runtime effect, configuration, or product intent still needs confirmation. Severity reflects the potential impact on this care app. The baseline has not been tested on a fresh database, and the account checks below were not run.

**Findings** — 0 Critical, 5 High, 24 Medium, 49 Low.

## Export and evidence

- [Schema baseline](../supabase/migrations/0000_baseline.sql#L1) contains 13 public tables, 108 columns, 74 constraints, 30 indexes (including 15 constraint indexes), 30 RLS policies, 24 public functions, one private trigger function, and five application triggers. There were zero public views, materialized views, sequences, standalone custom types, or publication enrollments in the inspected catalogs. The baseline records the extension inventory and assumes an initialized Supabase PostgreSQL 17 project with the managed roles and `auth.users`. It recreates the existing object grants without changing Supabase's default privileges for future objects.
- [Deployed handoff-brief](../supabase/functions/handoff-brief/index.ts#L1) was exported. [Existing home-digest](../supabase/functions/home-digest/index.ts#L127) was preserved. Its deployed source differs as documented below.
- No production tables or users were queried. No function was invoked, no care payload was sent, and no live change was applied. Gemini billing, retention, and consent were outside the metadata available in this review. [Gemini API terms](https://ai.google.dev/gemini-api/terms)

Claim locks the membership row before the shift and atomically updates an open assignment. The leave DELETE conflicts with that membership lock. Mark and undo serialize stock changes on the item row, and undo conditionally changes the dose from `taken` before restoring stock. Stock adjustment also locks the item before changing its balance. Join requests use a unique circle/user key, a row lock when reopening a previous request, and conflict handling on insertion. Review locks a pending request, checks circle creator and a non-null decision, and adds membership at most once. A declined request stays declined.
